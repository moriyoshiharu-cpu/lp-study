# LP学習プロジェクト

LP（ランディングページ）とSEOを、実物を触りながら理解するための学習用リポジトリ。

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | 架空サービス「Funnel」のLP。CSS・JSを1ファイルに内包 |
| `README.md` | このファイル |

`index.html` をダブルクリックするとブラウザで開きます。外部サーバーもインストールも不要です。

## LPの構造（このファイルの中身）

上から順に、以下のブロックで構成されています。HTMLファイル内の各ブロック直前に「なぜこれがあるか」のコメントを書いてあります。

```
 ① ファーストビュー   キャッチ＋CTA        ← ここで7割が決まる
 ② 課題提起          「こんなことないですか」  ← 共感
 ③ 解決策・できること  変化を示す            ← 機能ではなくベネフィット
 ④ 数値実績          信頼の担保
 ⑤ 進め方            3ステップ             ← 面倒くささを消す
 ⑥ 導入事例          第三者の声
 ⑦ 料金             出すか隠すかの戦略判断
 ⑧ FAQ              最後の不安つぶし
 ⑨ 最終CTA・フォーム   ゴール
```

CTA（Call To Action＝行動喚起ボタン）は、ファーストビュー・中盤・最後と**3〜5回**繰り返し配置しています。

## 学習ステップ

### STEP 1：開いて見る ✅

`index.html` をブラウザで開く。スクロールして構造を確認する。
ブラウザの幅を狭めると、スマホ表示に切り替わることも確認する。

### STEP 2：書き換えてみる

メモ帳でもVS Codeでも構いません。`index.html` を開いて以下を変更 → 保存 → ブラウザで F5。

**課題A：色を変える**
```
ファイル上部の  --brand: #3b5bfd;  を好きな色コードに変える
→ ページ全体の色が一括で変わることを確認
```

**課題B：キャッチコピーを変える**
```
<h1>流入は足りている。<br><span class="grad">詰まっているのは、その先だ。</span></h1>
→ 自分の言葉で書き換えてみる
```

**課題C：★最重要★ 「絞るLP」を「集めるLP」に戻す**
```
フォーム内の「▼ ここから3問が絞るための質問 ▼」から
「▲ ここまで ▲」までの3つの <div class="field"> を削除する

→ 登録が一気にラクになる（＝リードは増える）
→ でも相手が誰か分からなくなる（＝営業が困る）

この差が、マーケとISの利害対立の正体です。
```

### STEP 3：Gitで管理する ✅

実行済み。使ったコマンドは以下の3つ。

```bash
cd C:\Users\0718aa\lp-study
git init -b main            # このフォルダをGit管理下に置く（-b main はブランチ名の指定）
git add .                   # 記録対象に入れる（. は「全部」の意味）
git commit -m "メッセージ"   # セーブポイントを作る
```

#### 覚えるべきコマンドは6つだけ

| コマンド | 意味 | いつ使う |
|---|---|---|
| `git status` | 今の状態を見る | **迷ったらまずこれ** |
| `git add .` | 記録対象に入れる | 変更したあと |
| `git commit -m "..."` | セーブする | キリのいいところで |
| `git log --oneline` | 履歴を一覧で見る | 過去を確認するとき |
| `git diff` | 変更箇所を見る | commitする前の確認 |
| `git restore ファイル名` | **変更を取り消す** | **壊したとき** |

`add` と `commit` が分かれているのは、買い物と同じ理由です。

```
git add     = 買い物かごに入れる（まだ確定しない・選び直せる）
git commit  = レジで会計する（レシート＝履歴が残る）
```

10個変更しても「今回は3個だけ記録する」ができる。これが分離の理由です。

**`git restore` が命綱**。これがあるから安心して壊せます。
STEP 2で何をどう壊しても、必ず戻れます。

### STEP 4：GitHubに上げて公開する ✅

- **公開URL**： https://moriyoshiharu-cpu.github.io/lp-study/
- **リポジトリ**： https://github.com/moriyoshiharu-cpu/lp-study

#### 使ったコマンド（GitHub CLI）

```bash
gh auth login                # GitHubにログイン（初回のみ・ブラウザ認証）

# リポジトリ作成 + remote登録 + push を一度に実行
gh repo create lp-study --public --source=. --remote=origin --push

# GitHub Pages を有効化（Web画面の Settings → Pages と同じこと）
gh api --method POST "/repos/<ユーザー名>/lp-study/pages" -f "source[branch]=main" -f "source[path]=/"
```

Web画面から行う場合は、リポジトリの **Settings → Pages → Branch を `main`** にして Save。

#### 以降、サイトを更新する流れ

ファイルを書き換えたら、この3つを打つだけで公開サイトにも反映されます。

```bash
git add .
git commit -m "何を変えたか"
git push
```

反映まで1〜3分かかります。

**ここが重要**：公開しないとSEOは学べません。URLがないとGoogleに登録できないからです。

#### GitとGitHubの違い（混同しやすい）

```
【Git】                       【GitHub】
自分のPCの中で動く道具          インターネット上の置き場所
・変更履歴を記録する            ・Gitの履歴をアップして保管
・いつでも過去に戻せる          ・他人と共同編集できる
・オフラインで完結              ・無料でWeb公開できる（GitHub Pages）
```

Git ＝ ゲームのセーブ機能、GitHub ＝ セーブデータのクラウド保存、と考えると分かりやすいです。

### STEP 5：SEOを実際に体験する

1. [Google Search Console](https://search.google.com/search-console) に STEP 4 のURLを登録
2. 「URL検査」からインデックス登録をリクエスト
3. 数日〜2週間待つ
4. 「検索パフォーマンス」で、どのキーワードで表示されたかを確認

ここまで来ると、
- `<title>` を変えると検索結果の見出しが変わる
- `meta description` を変えるとクリック率が変わる
- 表示速度が順位に影響する

といったことが、**実感として**分かるようになります。

## グラフの作り方（データ可視化の原則）

このLPには3つのグラフが入っています。それぞれ「よくある失敗」を避ける形で作ってあります。

| # | 場所 | グラフ | 学べること |
|---|---|---|---|
| 0 | ファーストビュー | ファネル図 | 順序のあるデータは**単色の濃淡**で表す |
| ① | 課題セクション | 折れ線2本 | **2軸グラフを作らない**ための指数化 |
| ② | 解決策01 | 横棒の比較 | スケールが違うなら**グラフを分けて注記する** |
| ③ | 解決策の最後 | 折れ線2本 | **ROIは期間を決めないと計算できない** |

### 守っているルール

**1. 2軸グラフは絶対に作らない**

左右に別々の目盛りを置くグラフは、2つの軸の合わせ方が作り手の任意なので、
存在しない相関を勝手に作り出します。データ可視化で最もやってはいけない表現です。
→ グラフ①では、両方を「4月＝100」の指数に直して1本の軸に乗せています。

**2. 色は目視で決めず、検証する**

このLPのグラフの色は、色覚多様性（色の見え方が異なる方）でも区別できるか、
検証スクリプトで数値チェックして決めています。

```
系列1(青) ↔ 系列2(ティール)  識別距離 ΔE 28.8（基準：8以上）
通常視での識別距離           ΔE 32.6（基準：15以上）
```

「見た目で違うから大丈夫」は通用しません。日本人男性の約5%が色覚特性を持ちます。

**3. 順序のあるデータは単色の濃淡**

訪問 → 資料請求 → 商談 のように順番に意味があるデータは、
バラバラの色ではなく「薄い→濃い」の単色ランプを使います。色そのものが順序を語ります。

**4. 数字を全部書かない**

端の値だけ直接書き、残りは軸とマウスホバーに任せます。
全点に数字を書くと、かえって何も読まれなくなります。

**5. 色だけに意味を持たせない**

凡例・直接ラベル・表ビュー（「数値を表で見る」）の3つを併用しています。
色が見分けられない環境・人でも、必ず値に到達できる経路を残します。
