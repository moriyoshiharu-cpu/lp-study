#
#   robots.txt は「ドメインのルート」に置かないとクローラーに読まれません。
#
#     クローラーが見に行く場所：
#       https://moriyoshiharu-cpu.github.io/robots.txt          ← 404（無い）
#     実際に置いてある場所：
#       https://moriyoshiharu-cpu.github.io/lp-study/robots.txt ← 見に来ない
#
#   理由：GitHub Pages の「プロジェクトサイト」はサブディレクトリ配信のため、
#         ルートを持てません。ルートに置きたい場合は
#         「moriyoshiharu-cpu.github.io」という名前のリポジトリを作る必要があります。
#
#   実害：ありません。robots.txt が無い場合は「全ページ巡回可」が既定の動作なので、
#         結果的に望みどおりの挙動になります。
#
#   教訓：★ファイルを作った ≠ 機能している★
#         必ず公開URLにアクセスして検証すること。
#         （sitemap.xml は Search Console から直接送信できるので、こちらは有効です）
# ==========================================================================
#
# --------------------------------------------------------------------------
# 以下、robots.txt そのものの解説
# --------------------------------------------------------------------------
# 検索エンジンのクローラー（サイトを巡回するロボット）への指示書。
# サイトの一番上の階層に置くのが決まりで、クローラーは最初にこれを読みに来ます。
#
# 【重要な誤解】
#   robots.txt は「見せない」ための仕組みではありません。
#   あくまで「巡回しないでください」というお願いで、強制力はなく、
#   ファイル自体は誰でも見られます（このファイルも公開されています）。
#   本当に隠したいものは、そもそも公開サーバーに置いてはいけません。
#
# 【実務でよくある事故】
#   開発中に "Disallow: /" （全ページ巡回禁止）にしたまま本番公開してしまい、
#   何ヶ月も検索結果に出ない、という事故が定番です。
#   SEOの調子が悪いとき、まずここを疑うのがセオリー。
# --------------------------------------------------------------------------

# User-agent: * = すべてのクローラーが対象
User-agent: *

# Allow: / = サイト全体の巡回を許可
Allow: /

# サイトマップの場所を教える（絶対URLで書く決まり）
Sitemap: https://moriyoshiharu-cpu.github.io/lp-study/sitemap.xml
